# 稳定事实与风险

## 必读事实

- 产品已确定为求职能力证明作品；2026-09-22 用户已授权质量闭环工程实施，Panda增量已限定交付。行业痛点仍缺直接用户证据，预设结果不能证明真实策略优劣。
- 外部证据表明机器人开发已经出现围绕数据采集、运行检索、实时/回放调试、跨运行对比、数据集管理和策略评测的产品与开源工具链；这支持“任务验证/观测/评测”方向存在市场类别需求，但不等于本项目已完成需求验证。
- 当前仓库有 V1 模拟流程、旧 V2 平面任务与 Panda 接触抓放/完整几何回放。标准 benchmark、传感器接入、VLM/VLA、真机与生产交付未完成。
- 对目标为计算机背景、偏交互和售前/解决方案产品工程的用户，VLM/VLA 更适合作为可接入、可解释、可评测的能力，而不是要求从零训练模型或深入机械控制。
- 本项目的首要目标是求职能力证明；V2 的主评价对象是招聘方/技术面试官，代表性领域用户用于校准任务流程。项目应优先展示领域理解、开源接入、受控评测、失败解释和技术交付能力。
- V2 的系统边界保持为“现有 Streamlit 平台 + 独立仿真执行器 + 版本化运行记录”：平台负责启动、状态轮询、回放、比较和报告，仿真器负责产生执行数据，不做网页实时控制。
- 当前为原生 MuJoCo Panda，保留历史平面路径；robosuite PickPlaceSingle 是历史候选，不作为当前前置。模型来源、判据与PID资源基线见最终交接。
- 用户希望第一阶段探索实时仿真、多任务、多机器人和 VLA/相关模型能力；需要明确这四者分别依赖环境、数据集、策略和平台适配，不能把一个数据集当成完整系统。
- 当前公开资源候选：RoboCasa365 适合多任务仿真和 LeRobot 格式数据；Open X-Embodiment 适合多机器人示范数据与 RLDS 统一格式；DROID 适合真实机器人多任务数据但体量很大；robomimic 适合较小规模的仿真/真实操作示范和离线学习；ManiSkill/Isaac Lab 更偏多机器人、多任务仿真环境。
- 数据源初期应使用小规模调试样本或单任务数据，先完成一条实时执行与记录链路；不直接下载完整 DROID、Open X 或 RoboCasa 数据集，也不同时承诺多机器人并行、VLA 训练和实时网页控制。
- 本机适合的最小项目切片为“一台机器人 + 一个抓取放置任务 + 两个脚本策略/参数版本 + 运行记录 + 现有平台回放比较”。外部大数据集不是这个切片的必要前置。
- Intel 集成显卡且无 NVIDIA CUDA；Isaac Lab、全量 RoboCasa、多机器人并行和本地 VLA 训练不作为第一阶段目标。必要时可用远程推理或预生成数据，但必须标明其不是本机实时推理。
- 后端实现前必须先定义测试工程师任务和最小测试案例；测试案例同时作为 worker、运行产物、平台展示和成功判定的验收契约。
- 用户补充调研建议优先做“机器人软件平台、数据与评测产品”，兼顾任务能力与仿真工具；V2 主用户暂定为机械臂任务验证人员，用户画像仍需 3-5 位真实实验/验证人员访谈验证。
- 用户补充调研提出 V2 的核心变化为“有流程可演示 → 有数据可追溯 → 有比较规则 → 有人能够独立使用并复查结论”。
- 用户补充调研提出最小仿真范围为一台机械臂、一类物体、一个抓取放置任务、两版策略；优先做离线仿真执行、运行记录导出和导入现有工作台，不先做网页实时控制。
- 当前产品是本地单用户 Pick & Place 任务验证 MVP，V1 为模拟演示，V2 为简化物理任务；真实机器人控制不在范围内。
- V1 的事实来自 `simulator.py`；V2 的物理状态来自 `v2_physics.py`，运行生命周期来自 worker/JobManager，前端不拥有成功结论。
- `data/store.json` 只承载 V1；V2 按运行写入独立目录。两者均未实现多人并发保障。
- Python 与 Three.js 之间的主要跨模块契约是 `RendererPayload`；前端只负责展示和帧采样。
- V2 已使用原生 MuJoCo 3.13.0 在当前 Windows/Python 3.12 CPU 环境跑通轻量平面任务；不依赖 robosuite、CUDA 或外部大数据集。
- V2 运行事实存储为 `data/v2_runs/<run_id>/` 下的 config/meta/status/trajectory/events/summary 文件；V1 `data/store.json` 不承载物理运行。
- V2 worker 在独立子进程运行，父进程只负责启动、轮询、超时和崩溃转换；Streamlit 页面不步进物理仿真。
- `v2_adapter` 将真实 `trajectory.jsonl` 映射到独立 V2 renderer，标记 `trajectory_source=mujoco-runtime`；当前 Chromium 位置示意回放已限定复核，不能外推到完整机械臂。

## 当前有效风险 / 坑

| ID | 风险或坑 | 影响 | 处理方式 |
|---|---|---|---|
| F001 | `input_params` 是开放字典 | 新功能容易形成隐式字段依赖 | 跨页面复用的字段写入接口契约；稳定后再 schema 化 |
| F002 | Panda已通过6关键帧真实mesh数值对照和Chromium独立复核 | 不能外推其他浏览器/视口 | 后续展示改动重跑对应浏览器入口，旧示意证据不替Panda |
| F003 | `md/项目结构总览.md` 中的测试数量已过时 | 接手者可能误判验证覆盖 | 以实际测试结果和 README 为准，并在文档治理阶段修正 |
| F004 | 市场中已有 Foxglove 等成熟机器人数据工作台 | 直接复制“可视化+回放”会缺少差异化 | 需要明确 VLA 评测、失败解释、售前演示或客户交付中的独特价值 |
| F005 | 真实 VLA 评测依赖 GPU、Docker、模型/benchmark 版本和数据协议 | 项目容易变成环境安装工程 | 先选一个可复现的轻量路径，记录硬件、版本、seed、episode 和结果证据 |
| F006 | Panda固定场景已实测，完整真机与泛化未验证 | 不能把固定条件3+3重复当作场景覆盖 | 保留脚本/特权位姿/接触仿真边界，不外推生产稳定性 |
| F007 | 结束状态不等于任务成功，且随机种子不足以保证精确复现 | 可能产生错误成功率或无法复查的结论 | 单独定义 success 条件，并保存环境版本、初始状态和运行配置 |
| F008 | 观察、分类和原因推断可能被混为一谈 | 失败报告过度确定，误导策略判断 | 报告分开记录观察事实、失败分类、可能原因和证据不足 |
| F009 | 个人项目暂时难以招募目标用户 | 需求阶段可能长期停滞，或把自我推演误写成用户验证 | 将项目目标定义为能力证明；使用 A/B/C/D 证据等级，没有 A 级反馈时限制市场结论 |

## 环境与契约注意事项

- 2026-09-22 UI资源核验：[BoardUI官方](https://www.boardui.com/getting-started)为React系统，部分模块Pro；未取得代码/Pro授权且与Streamlit不直接兼容，未选用。[Watermelon](https://ui.watermelon.sh/)本次读取失败，未采用。[Navbar Gallery](https://www.navbar.gallery/)公开参考可访问，仅确认资源类型，未复制案例图片/代码。本批实际使用已安装Streamlit1.56.0和Three.js原生能力。
- V2业务语义以CONTEXT及接口契约第14节为准：实际参数决定方案分组；同参数重复不等于两版比较，不能以3次重复自动升级泛化证据。
- 运行查询由V2RunService集中提供，列表的metadata_only不是完整证据通过；统计、建议对比和实际比较需核验产物。缺报告的执行错误保持任务结果未知。
- 测试必须自行产生或携带输入，不依赖`.tmp-tests/panda-q4-*`等历史审查目录；本批已修复原比较回归的该依赖。
- 时间字段为 ISO 8601 字符串，时长和偏移量为毫秒整数。
- 运行状态为 `queued`、`running`、`succeeded`、`failed`、`cancelled`。
- V2 的 WebGL 异常可回退 SVG 示意；bundle 缺失时提示构建，报告仍可用，不宣称完整回放可用。任何展示降级不能改变业务结果。
- 当前调研候选：LeRobot 适合作为数据/策略/评估链路基础；AllenAI `vla-evaluation-harness` 适合作为跨模型/benchmark 的评测后端；ManiSkill 或 RoboCasa 适合作为仿真任务基座；Foxglove Studio/Rerun/MCAP 适合作为观测与回放生态参考或数据接入层。暂未决定 fork 哪个项目。
- Panda采用v2.1模型/几何姿态契约，旧平面v2.0仍为工具点示意；详见 [最终交接](../docs/Panda实施与门禁.md#handoff-panda-delivery-06)。

## Panda 模型来源与接入边界（2026-09-22）

- 已核对上游 [Panda 模型说明](https://github.com/google-deepmind/mujoco_menagerie/tree/main/franka_emika_panda) 和 [模型 XML](https://raw.githubusercontent.com/google-deepmind/mujoco_menagerie/main/franka_emika_panda/panda.xml)：包含机械臂、双指、视觉和碰撞几何、驱动配置；不是可直接保证成功的抓放控制器。
- 模型已固定到commit `822c2d8f877dd166c5b7d3c9f7e3c3b6589473b7`，71个必要资产/许可文件保存在assets/robots/panda；清单指纹与文件哈希校验，不增加训练或生产包依赖。
- 本机 Core Ultra 5 225H、约31.5GB内存、Arc130T核显，Python3.12.8/MuJoCo3.13.0；Panda独立worker PID核对峰值约291～292MiB，当前14s片段墙钟约1.76～8.63s。不能与包含Renderer的早期作者进程峰值混算。
- 当前平面任务的抓取使用工具—物体 weld，并由参数容差控制激活；成功仅看末帧位置/高度，不能证明连续稳定窗口。新接触任务须替换这两类判据；保留历史产物语义。
- Panda比较在模型/评估/初态检查前校验实际scene/轨迹/事件和结果终态，损坏输入拒绝统计；独立Q4已核对关闭漏校验问题。
- 超时已同时覆盖wait与poll；终态返回前回收进程/管道，错误日志先落盘再发布失败。页面crash/timeout及再次启动已实测。

## V2 需求证据框架

- 需求校准交付物：3-5 位实际做过机械臂实验或任务验证人员的真实流程记录，明确改动、数据、手工整理、结论接收者和最易出错步骤。
- 单次仿真交付物：实际执行产生的运行记录，包含策略版本/参数、场景配置、初始状态、环境版本、逐步状态和关键事件；演示数据与仿真数据必须区分。
- 受控比较规则：相同初始状态集合、相同场景和指标定义，明确唯一改动；同时展示总体结果和分场景结果，允许输出“证据不足”。
- 失败证据规则：分别记录观察、失败分类、可能原因和未知项；不能把 done 直接当作成功，也不能仅凭一个随机种子宣称精确复现。
- 产品有效性试用：让使用者用未提前演示的数据独立找出退化场景、定位证据并提出下一步验证；观察结论正确性、完成时间、求助次数和操作障碍。

## 外部研究结论

- Foxglove 的官方产品覆盖机器人数据采集、运行检索、实时与录制数据可视化、问题定位、跨运行同步比较和团队共享，说明“机器人运行观察与验证”不是纯概念需求。
- Hugging Face LeRobot 把数据集、策略、环境、真实机器人、回放、训练、评估和可视化放在一套工作流中，说明“数据—策略—评估”的闭环正在成为具身智能开发基础设施。
- AllenAI `vla-evaluation-harness` 明确将模型与 benchmark 解耦，用 Docker 和结果 JSON 支持跨环境评测，说明当前生态痛点已经从“做一个 demo”转向“统一、复现、比较评测”。
- XDOF 的 Forward Deployed Engineer、Foxglove 的 Robotics Solutions Engineer、Moonlake 的 GTM Engineer 等岗位共同强调客户需求转化、技术方案设计、数据/系统集成、QA、技术 demo 和产品反馈；这与售前/解决方案产品工程目标比纯模型训练岗位更接近。

## 历史候选开源基础的判断

以下保留早期生态调研，不代表当前增量选型；当前首选原生 MuJoCo + Panda，其他候选不构成本轮安装清单。

| 候选 | 适合承载的部分 | 主要代价 | 当前判断 |
|---|---|---|---|
| Hugging Face LeRobot | 数据集、策略、机器人/仿真环境、训练/评估/回放工作流 | 依赖 PyTorch、模型和硬件生态，范围很大 | 最适合作为目标用户方向的主链路基础 |
| AllenAI vla-evaluation-harness | 模型服务、benchmark 适配、批量评测、结果 JSON | Docker/GPU/依赖体量较重，UI 不是重点 | 最适合作为评测后端或二期接入 |
| ManiSkill | 操作任务仿真、演示数据和策略评测 | 需要适应仿真 API 与 GPU 环境 | 适合作为轻量仿真 benchmark 候选 |
| RoboCasa365 | 多任务、长时程、家庭场景和更丰富的 benchmark | 资产、环境和计算量较大 | 适合作为后续展示泛化能力的扩展 |
| Foxglove Studio / MCAP | 真实机器人日志、时间同步、多模态回放、观测体验 | Foxglove 是成熟产品且采用 open-core；直接 fork 会与其同质化 | 适合作为数据标准/交互参考，不建议直接复制产品定位 |
| Isaac Lab | 高保真、多模态、GPU 并行仿真 | Isaac Sim 依赖和许可边界更重，学习成本高 | 不作为当前第一基础 |
