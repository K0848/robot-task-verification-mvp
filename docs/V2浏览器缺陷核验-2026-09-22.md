## Findings

| ID | 严重程度 | 实际观察和原因 | 处置状态 |
|---|---|---|---|
| VIS-01 | 关键 Major | 成功/失败结果出现后，Three.js 始终显示 approach、0%；页面没有播放/暂停/时间轴。adapter 固定 `animation.mode=static`、`initial_elapsed_ms=0`，页面未提供时间驱动。是功能缺失，不只是画面需要美化。 | Accept / Open |
| VIS-02 | 关键 Major | worker 已终态，启动与清除按钮仍禁用；更换策略触发整页重跑才恢复。按钮在 fragment 外，只有状态区域按秒重跑，按钮的 `active` 未随终态更新。 | Accept / Open |
| VIS-03 | 关键 Major | 切换 SVG 后浏览器直接展示 SVG 源码块。Markdown/HTML 混合及缩进导致代码块；同时 SVG 仍用 V1 的 x×3、y×2，MuJoCo 米制位置映射到原点附近甚至负坐标，并忽略高度。SVG 用最后帧，Three.js 用第一帧，切换渲染器也未保持同一时刻。 | Accept / Open |
| VIS-04 | Major | 深色页面中的原生 metric 和标签仍是深色文字，按钮、选择器、报告又沿用浅色表面。截图可见成功/失败和轨迹指标可读性差；V2 报告只有大块 `st.json(summary)`，没有规划中的证据分层/时间联动。 | Accept / Open |
| VIS-05 | 关键 Major | 源码核对发现 V2 仍调用共用 `sampleFrame()`，其物体 x/y 仍走 V1 `blendObjectPosition`（保持或 snap），并非所有坐标线性采样；机械臂肘部和物体旋转也仍由前端构造。`mujoco-world` 标记不能证明整幅画面真实重建。静态首帧掩盖了动态缺陷。 | Accept / Open |

## 覆盖与边界

- Pass（本次范围）：本地页面能打开；页面按钮能发起真实 worker；baseline 显示 succeeded、偏移显示 failed；两者均有 131 帧、`mujoco-runtime`；结果字段与生成产物一致；WebGL canvas 存在，本轮无浏览器 pageerror。
- Finding：真实播放、交互恢复、SVG 降级、主题可读性、物理轨迹采样/几何标识。

- 未改生产代码、未宣称修复；没有重跑与这些缺陷无关的旧单测来替代浏览器证据。

### 本轮执行契约

- 保留 V1、worker、artifact 和成功规则，不通过改结果来让画面通过。
- V2 独立回放视图（复用既有 bundle/Three.js），浏览器单一播放时钟控制工具、物体、时间轴、事件和数值；播放只读，暂停不暂停 worker。
- 物理帧独立线性采样，布尔/阶段采用左帧保持直到下一采样点；记录坐标不被 held/placed 标签改写。只显示工具/物体/目标示意，明确非真实机器人几何重建。
- Three.js 与 SVG 共用采样函数、米制坐标和时刻；手动切换保持时刻，WebGL 失败自动回退 SVG。原始产物缺失时显式报错，不替换成 V1 数据。
- worker 终态仅触发一次页面级刷新恢复按钮；回放区不再每秒重建。运行状态与回放时刻分开显示。
- 结构化报告与 summary 同源，原始 JSON 可展开查看；不新增预测或根因推断。
- 验证：类型/采样单测及 Python 相关回归；真实 Chromium 测 baseline、offset、暂停/继续、拖动、事件跳转、SVG 同时刻坐标、连续启动、强制 WebGL 失败和 V1 入口。截图、断言和控制台错误记录落在 docs/evidence。
