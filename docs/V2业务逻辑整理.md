# V2 业务逻辑整理

## 范围与边界

2026-09-22 用户要求先处理后端业务逻辑，再整理前端效果。本批建立可由页面/CLI共同消费的 V2 业务入口；保持原生物理任务、成功判据、V1历史记录、Three.js 和视觉样式不变，不换数据库或新增依赖。

已发现：页面自行扫描记录并静默跳过异常；默认比较最近两条可能都为baseline；同参数重复仍被称为版本比较；按方案标签分组可能掩盖同名不同参数；部分测试依赖未跟踪的`.tmp-tests`复现文件，换机器无法独立运行。

业务术语见 [CONTEXT](../CONTEXT.md)，它只定义概念，不承担技术契约。

## 本批执行与验收

| 工作 | 验收标准 |
|---|---|
| 统一运行查询 | 默认Panda，按模型/状态/诊断标记查询与分页；运行中、无报告的执行异常、损坏记录均有状态/原因，不静默消失；不读取V1 store |
| 历史详情与当前引用分离 | 给定run ID可读取状态、结果或回放，不依赖页面还持有JobHandle；读取不能修改原始结果；旧记录无新增时间字段时有明确兼容来源 |
| 统一参数入口 | 页面从后端获取现有两个参数方案并创建配置；页面不再硬编码偏移值。底层CLI研究用自定义标签保持兼容 |
| 比较语义 | 相同参数为重复性检查，不同参数为受控参数比较；名称不是分组依据；跨模型/条件/损坏/重复run拒绝，不输出误导统计 |
| 合理默认比较 | 后端建议一条完整基线与同条件不同参数记录；只有同参数时不伪装成两版比较。选中前检验，执行比较时再次检验 |
| 统计与证据 | 汇总只统计该模型的有效任务报告，基础设施失败/未知/损坏单列；无有效分母时成功率为null，不填0；明确固定条件样本范围 |
| 接线与回归 | 当前页面最小接线，不改导航/样式；CLI提供list/show/overview入口；真实worker→查询→回放→比较可运行，测试不依赖临时历史文件 |

## 设计选择

- 新增 `V2RunService` 作为本地应用业务服务，调用既有 JobManager/ArtifactStore 和已验证的回放适配器；不新增HTTP服务或通用插件层。
- 查询列表只验证轻量记录元数据，并标明证据尚未完整校验；详情可要求完整证据校验。统计/建议比较/实际比较必须验证真实产物，不让轻量列表标记冒充完整验证。
- 列表返回 `items/total/offset/limit/has_more/issues`；失败信息也是结果，不以吞掉异常制造空列表。范围默认Panda，历史平面显式选择，诊断注入默认排除。
- 详情区分记录状态、任务结果、证据完整性和可用能力；记录还在运行但本服务没有进程句柄时，仅描述持久化状态，不猜测进程仍存活或擅自写终态。
- 比较保留既有返回字段兼容；新增 `comparison_kind`、实际参数分组及建议pair。固定初态重复数量不自动升级成充分证据，允许检查差异但不输出上线推荐。
- 当前进程启动/超时/回收沿用已验收实现。本批不承诺跨进程全局单任务锁、多用户调度或服务器重启后接管外部进程。

## 已实现接口与运行方式

实现入口：`robot_mvp/v2_service.py`；比较与统一报告校验复用`v2_runtime.py`；当前V2页面和CLI已接线，前端没有重新解释参数或扫描记录目录。

```powershell
python -m robot_mvp.v2_cli list --limit 20 --offset 0
python -m robot_mvp.v2_cli show <run-id>
python -m robot_mvp.v2_cli overview
python -m unittest discover -s tests -v
```

列表默认Panda，`--model minimal_planar_pick_place`显式查历史平面，`--include-diagnostics`才包含故障注入记录。`show`可以在新进程中复查历史数据，不需要上次页面的JobHandle。`compare`输入被拒绝时保留结构化报告并退出2。

## 前端阶段承接

1. “验证工作台”消费`models/presets/start_run/poll/get_run/replay_payload`，不自行推断业务成功或生成参数。
2. “运行记录”消费`list_runs/get_run`并使用分页与完整性状态，不再借用V1历史列表；异常行不能静默消失。
3. 比较消费`suggest_comparison/compare`；同参数结果标为重复性检查，非受控输入显示拒绝原因。用户选择记录的权利保留，不擅自替换已选记录。
4. 首页若展示统计必须调用明确模型范围的`overview`并说明分母、未知与无效项，不能迁用V1健康排名。
5. 原始JSON/坐标/帧数等可折叠，但状态、结果依据和失败恢复不能删除。历史演示收纳、角色选择移除、默认导航和视觉效果属于下一前端阶段，不写成已完成。

运行查询仍以本地小规模文件目录为范围；大量历史的检索延迟未做容量测试。跨进程单任务锁、服务重启后的进程接管、删除/取消运行没有新增承诺。来源不明条目进入issues；CLI汇总是描述性运行总数，不是策略benchmark或生产成功率。

## 前端整理：规格转译与设计约束

2026-09-22用户显式启用spec-driven-ui-design并授权继续优化。该skill负责设计转译和资源判断，实际前端代码按项目工程规则实施；沿用planning-with-files-zh维护本批状态。既定结构为“验证工作台 / 运行记录”，不另开产品方向投票或建立不接真实数据的第二套演示。

| 来源/状态 | 约束与适配 |
|---|---|
| 已确认：PRD V2.8D/E及业务服务 | 单Panda、参数选择→运行→回放→比较；运行记录不借用V1；失败/未知/证据不足不能隐藏 |
| 已观察：现有深色界面与Three.js | 保留深色底、青色强调与现有系统字体；复用既有播放器，不重画机器人或修改时间/姿态契约 |
| 本批UI决定：主导航 | 顶部保留两个主入口；默认验证工作台。帮助、V1演示和旧平面放到次级入口，明确来源并可返回主流程 |
| 本批UI决定：工作台 | 单任务/模型以说明呈现；保留参数方案和开始验证。显示真实最近/选中运行，运行态与回放态分开；移除清除引用、角色切换和无来源全局健康指标 |
| 本批UI决定：历史 | 使用原生分页记录列表、状态筛选、可读状态标签与查看按钮；坏记录和执行错误可见。打开记录后在工作台复查，不依赖原进程句柄 |
| 本批UI决定：信息层级 | 成功/失败、仿真时长、证据状态和简短结论在主层；帧数、坐标、模型ID、环境与JSON折叠。3D主视图保留播放/时间轴/事件；渲染设置和技术值收起，WebGL降级提示始终可见 |
| 实现资源：available | 当前Streamlit1.56.0原生容器、单选导航、选择器、状态提示、按钮、表格/列表和expander，加现有Three.js；不新增依赖或外部字体/脚本 |
| 候选核验 | BoardUI公开资料确认是React设计系统，当前项目不直接兼容；其Pro内容不使用，但免费部分仍可在兼容项目中逐组件核验。Watermelon官方页面本次不可读取，暂不选用；Navbar Gallery只确认公开参考入口，不复用图片/代码。当前项目实际使用Streamlit/Three.js原生能力 |

本次选择“已有结构的代表性页面直接落地并检查真实状态”，不新建静态HTML假数据原型。没有授权或兼容性证据的外部组件不使用，也不声称调用了BoardUI/MCP。资源核验来源与日期见findings。后续若用户指定采用某一React/商业库，再单独确认迁移或授权。

验收：首次进入不展示旧V1指标；可启动正常/偏移运行；主流程没有角色/模型/清除引用选择；历史分页/筛选/错误提示/打开详情正确；比较展示参数组与结论，原始JSON可展开与导出；帮助/历史入口可返回；桌面与约600px面板检查不裁切关键控件，键盘焦点可见；原播放器不自动播放，避免无关动效。
