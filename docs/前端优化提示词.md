# Robots 前端优化提示词

请在当前 Robots 项目中优化前端界面。

## 项目约束

- 当前技术栈是 Streamlit + Python + Three.js，不要为了套用 React 设计系统而迁移技术栈。
- 后端业务入口是 `robot_mvp.v2_service.V2RunService`；前端不能自行扫描运行目录、重新解释成功判据、拼接统计或修改运行结果。
- Panda 物理仿真、运行记录、比较规则和失败证据已经稳定。前端优化不能改变这些业务规则。
- V1 演示数据、旧平面任务和 V2 Panda 运行必须保持数据来源隔离。

## 组件与资源规则

- 优先检查项目已有组件和兼容的免费、开源或社区组件；当前项目可用的原生平替包括 `st.container`、`st.columns`、`st.radio`、`st.selectbox`、`st.button`、`st.status`、`st.expander`、`st.popover`、`st.dataframe`、`st.tabs` 和已有 Three.js 播放器。
- 需要数据表、状态卡、筛选、分页、折叠详情和导航时，选择最适合当前技术栈的已授权组件；只有没有合适免费组件时才使用原生组合或本地实现。
- 外部组件库可以使用，但必须与当前技术栈兼容、当前环境可安装或已连接、具体组件许可证清楚、无需未确认的付费或账户权限，并且确实能减少维护成本。
- “Pro”只表示某个外部资源的付费版本或受限内容，不表示用户能力等级。只移除 Pro、付费、授权不明的部分，不能把同一资源的免费/开源部分一并删除。
- 如果候选资源是 React、未连接的 MCP、许可不清或无法核验，不能复制其代码或假装已经调用；先选择兼容的免费资源，没有合适候选时才使用当前项目原生组件或本地实现。
- 公开设计参考可以借鉴信息层级、布局关系和交互模式，但不复制受限代码、图片、品牌或未授权素材。

## 产品目标

主入口围绕一条任务链：

> 选择参数方案 → 开始验证 → 查看运行状态 → 回放动作与事件 → 读取证据 → 比较运行。

页面应优先让用户理解：当前运行是什么、结果是什么、证据是否完整、下一步能做什么。

## 页面结构

- 默认进入“验证工作台”，不要先展示 V1 的模拟成功率或旧策略健康看板。
- “运行记录”负责按模型、状态和诊断标记查询，支持分页、异常提示和打开历史运行。
- V1 演示与旧平面任务放入“帮助与历史”等次级入口，不能混入 Panda 统计。
- 回放主区域保留播放、暂停、时间轴和事件定位。
- 技术详情、原始 JSON、坐标、模型 ID、运行 ID和环境信息放进折叠区域。
- 失败观察、失败分类、可能原因和未知项必须可见；不能用动画替代证据。

## 状态与错误

- `queued`、`running`、`succeeded`、`failed`、`cancelled` 和未知状态必须有明确显示。
- 执行异常不能直接显示成任务失败；如果没有有效任务报告，应显示“任务结果未判定”。
- 损坏记录不能静默隐藏，也不能显示为成功；应显示异常原因和可用的恢复路径。
- 运行记录查看不依赖当前页面仍持有 worker 句柄。
- 比较前必须由后端检查实际产物完整性和可比条件；前端只展示后端返回的比较分类与结论。

## 视觉和交互

- 沿用当前深色主题、青色状态强调和项目已有字体/按钮风格。
- 主行动只有一个：开始验证。比较、导出、技术详情属于次级操作。
- 不增加装饰性动效；回放动画只表达真实仿真记录。
- 检查桌面和约 600px 宽度面板下的关键控件可见、文字可读、焦点状态可见。
- 变化完成后至少验证空状态、运行中、成功、失败、损坏记录、历史打开、比较和回放路径。

## 交付要求

说明：实际修改、业务来源、使用的组件、资源授权状态、测试命令、浏览器验证、未验证范围和剩余风险。不要把“使用了设计 skill”写成“使用了某个未安装或未授权的组件库”。
