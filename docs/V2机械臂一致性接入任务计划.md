# V2 完整机械臂与夹爪接入任务计划

> 日期：2026-09-22 · 状态：S1～S6 已完成本批声明范围，独立 Q4 = Passed for limited scope；见 [最终交接](Panda实施与门禁.md#handoff-panda-delivery-06)。
> 规划交付后用户已授权按计划实施，当前进展见 [实施门禁](Panda实施与门禁.md)。资产接入和代码/测试在范围内，新增生产依赖和远程发布仍须确认。
> 产品依据：[PRD V2.8D](../PRD.md#v28d-完整机械臂与夹爪增量需求)。现有实现与本计划的目标必须分开表述。

## 1. 本次交付目标

用户在现有 V2 页面点击运行后，能够回放一台完整机械臂和双指夹爪执行方块抓取、抬升、搬运、放置与释放；画面对应同一次后端仿真的模型和状态，成功或失败可回指数据和事件。

本次提升的是模型及其展示的完整性，不承诺真机精度、行业标准 benchmark、机器人学习能力或 sim-to-real。脚本控制可以直接使用仿真物体位姿，必须标注不覆盖视觉感知误差。

### 当前起点与保留范围

- 已有：原生 MuJoCo 平面任务、独立 worker、运行产物、比较入口、独立回放播放器、事件定位与结构化报告。
- 已有局限：模型只有平移机构，抓取依赖工具与物体之间的 weld 约束；前端仅显示工具点、物体和目标，不能还原完整机械臂。
- 保留：Streamlit 页面框架、worker 隔离、V1/V2 数据分离、现有播放控件、TC-01～TC-05 和失败修复流程。复用能力仍需在新增路径回归，不能继承为自动通过。
- 修改：模型与控制、抓取/成功判定、模型资产和状态记录、adapter、完整机械臂渲染、比较的可比条件。
- 不删除旧运行、不覆盖用户工作区改动、不改 V1 行为；旧平面任务作为明确标记的历史兼容/回归路径，不进入 Panda 效果报告。

## 2. 方案与模块责任

首选原生 MuJoCo + Menagerie Panda 机械臂与配套夹爪；不引入 robosuite、ROS、WSL2 或 GPU 训练栈作为默认前置。模型来源核对见 [findings](../.claude/findings.md#panda-模型来源与接入边界2026-09-22)。

| 模块 | 本次责任 | 禁止越界 |
|---|---|---|
| 模型与场景包 | 固定上游版本，保存模型、所需网格、许可、项目场景和内容哈希 | 不能只导入好看的外壳，背后仍运行平移机构 |
| 任务控制与评估 | 脚本驱动关节和夹爪；计算接触、抬升、释放、落区及稳定窗口 | 不以参数值直接指定成功/失败；不使用工具—物体粘连代替接触抓取 |
| worker / JobManager | 加载确定版本、运行与记录、超时/异常收敛、退出回收 | 页面不步进物理；不得把运行结束当成抓取成功 |
| 产物与 adapter | 保存并验证模型身份、状态、几何姿态、时间、判定依据 | 缺字段不补成零姿态，不把旧平面产物升级成 Panda |
| 网页 renderer | 显示同源网格，按记录更新位置和朝向，复用回放控制 | 不自行求逆运动学、不补抓取吸附、不生成机器人关节动作 |
| 报告与比较 | 保留观察/分类/推断/未知，检查实验条件和样本范围 | 三次相同初始状态重复不是三种场景，也不自动证明策略全面改善 |

物体应由双指接触与摩擦支持。模型内部用于同步两根手指的约束不等于工具—物体粘连，不能误删；约束用途需要审计和说明。

首选网页继续提供可拖动时间轴的 Three.js 回放。MuJoCo 原生视图/关键帧用于独立对照；单独嵌入一段视频不是本次完整网页回放的替代交付。

## 3. 最小数据与兼容契约

`v2.0` 是旧平面任务产物；Panda 已使用 `v2.1` 机器人回放契约。以下字段组在数据层集中定义和校验，不由页面隐式补齐；实际字段见接口与数据契约第13节。

| 对象 | 必须保存的信息 | 校验与所有权 |
|---|---|---|
| 模型清单 | robot/model ID、上游 commit、许可证、模型与网格哈希、单位、关节/几何 ID 映射、项目场景版本 | 模型加载器拥有；本地固定资产，运行不依赖在线下载；路径限定在资产目录 |
| config / meta | run ID、策略/控制器版本、唯一受控参数、初始状态、MuJoCo/Python/平台版本、物理和评估配置、模型清单哈希 | 启动前冻结；元数据必须对应实际加载内容 |
| scene manifest | 从实际加载模型导出的网格/基础几何、材质、静态变换、ID 和内容引用 | 不重复每帧存网格；模型变更不能静默替换旧运行资产 |
| trajectory | 实际仿真时间、关节状态、控制输入、夹爪实际开度、物体位置/朝向、可见几何的世界姿态、阶段和必要接触证据 | MuJoCo 状态的副本；记录时间与采样后的状态一致；与控制意图区分 |
| events / summary | 阶段与事件时刻、抬升/接触/释放证据、目标区和稳定窗口指标、阈值版本、失败或未知 | 评估器拥有；稳定条件在物理步上计算，不仅检查回放末帧 |
| 性能记录 | 配置、冷/热加载耗时、墙钟执行耗时、仿真时长、进程内存、浏览器帧间隔、产物体积 | 测试入口拥有；不混淆仿真时间、执行速度和播放速度 |

### 几何与时间一致性

- 权威坐标为 MuJoCo 米制世界坐标。转换到 Three.js 时同时转换位置和朝向；现有 `[x,z,-y]` 只解决位置，不能直接套用到四元数。
- 明确四元数分量顺序、模型网格的局部原点/缩放和世界姿态，处理 MuJoCo 编译网格时的变换，防止重复旋转/平移。
- 首版优先整帧回放：同一显示时刻取不晚于该时刻的同一记录帧，机器人、物体、夹爪数值和阶段同步更新；显示实际采样时刻。末尾显示最后一帧。
- 不通过分别平滑每个部件来掩盖关节脱节。需要插值时另补一致性测试，不能影响事件时刻或判定。采样率与物理步长分开配置，首测以约 30 Hz 展示记录为候选，不降低物理精度换帧率。
- 轨迹缺失、ID 不匹配、非有限数、非法朝向、非单调时间或模型哈希不匹配，明确显示不可回放及原因；已有有效报告仍可查看。
- WebGL/模型展示失败时，可降级到明确标记的工具/物体 SVG 示意和数据报告，保留查看时刻；不能将降级画面算作完整机械臂验收通过。
- 旧 `v2.0` 继续按原有位置示意解释，不伪造关节字段；V1 不变。跨模型、模型哈希、场景、物理配置或评估口径不一致时，不输出受控策略优劣结论。

### 成功语义

成功必须同时具备抓取后抬升、到达目标、夹爪释放、物体在目标内稳定保持一段时间的证据。到达任务步数或脚本进入 release 阶段不等于成功；夹爪闭合指令也不等于夹住。

实施 S1 时依据模型尺寸和场景冻结：物体尺寸/质量、初始姿态、目标区域、离开支撑面的抬升高度与保持时间、实际释放判据、稳定位置/速度容差、稳定窗口、仿真及墙钟超时。它们是待测定的工程配置，不沿用旧平面任务的 `0.08m / 0.025m` 常量。阈值必须在正式验证前固定并写入产物，不能为了使某次运行成功而事后修改。改阈值后重新执行相关案例。

### 三个验收关口

1. **模型能运行（S1）**：看到完整机械臂和夹爪在原生环境运动；不是“能导入网格”就通过。
2. **任务有物理依据（S2～S3）**：成功和失败由实际接触与运动产生，产物可解释；不是“视频看起来抓住”就通过。
3. **网页与后端一致（S4～S6）**：页面完整显示、逐帧可核对、异常诚实、回归通过；不是“测试全绿”就免做浏览器检查。

S1 或 S2 未通过时，优先处理模型/控制/数据问题，不投入大量界面美化。纯工程修复由执行者完成；改用粘连抓取、视频替代交互回放、放弃完整模型、改为云端或更换运行系统属于实质取舍，需要用户确认。

| TC-05P 几何回放 | 播放/暂停/继续/拖动/倍速/事件定位；核对首帧、夹取前后、抬升、释放前后及末帧；连续运行不串数据 | 浏览器截图和断言、Three.js 实际对象世界变换与后端几何变换数值对照；不能只核对 DOM 镜像值 |

| P-07 资源与稳定运行 | 冷/热启动各记录，两个参数版本分别串行运行至少 3 次，交替打开回放并返回 | 各次运行耗时/内存/帧间隔/产物体积；无遗留 worker，几何和纹理释放；不是生产成功率样本 |

数值对照先在真实记录帧进行，位置建议容差 `1e-4 m`、旋转角差 `1e-3 rad`，作为序列化与坐标转换的初始工程精度预算；S1/S3 用导出精度校准并固定，不代表机器人实际定位精度。图像核对检查可见性和装配方向，不要求不同渲染器像素一致。

沿用失败闭环：重现并留证 → 分类到环境/模型/控制/评估/进程/数据/展示 → 最小修复 → 重跑失败案例 → 相关回归 → 更新限制。新独立审查只覆盖新增接触抓取、姿态映射、版本兼容、页面超时等变化及未关闭问题；历史 VIS 结论对未改动路径保留，不改写原报告为新模型通过。

## 6. 运行环境与资源预算

2026-09-22 本机会话已读取：Windows 11、Core Ultra 5 225H、约 31.5 GB 可用总内存、Intel Arc 130T 核显、Python 3.12.8、MuJoCo 3.13.0。检查时空闲内存约 7.6 GB，仅是瞬时值，不是固定可用预算；显卡名称中的 16 GB 不视作专用独显显存。

同日简单场景原生渲染检查生成 320×240 图像，只证明渲染能初始化，未证明完整 Panda 性能。本次不重复该检查，也不把它当成 S1 已通过。

以下是为了保留系统余量制定的**初始工程预算，非实测结果、非官方最低配置或已确认性能承诺**，S1 实测后冻结：

- 单用户、最多一个仿真 worker；重复评测串行；无 CUDA 或云端计算前置。
- 先测约 10 秒仿真片段，热启动墙钟执行目标不超过 30 秒；正式任务按阶段需要确定时长，另设有限墙钟超时，不混淆仿真秒数与执行秒数。
- worker 峰值内存目标不超过 2 GB；前端增量目标不超过 1 GB；分别记录平台、worker 和浏览器，不拿 JS heap 冒充浏览器总内存。
- 单视图约 1280×720、正常回放目标约 30 fps；记录测量窗口和帧间隔，不能只报告一次平均值。首次下载/加载单独计时。
- 状态流式写盘；网格按哈希复用；不常驻整段未压缩视频。保留运行产物，任何历史数据清理另行确认。

超出预算先分析网格数量、重复复制、采样、渲染分辨率与资源生命周期；不通过改写物理结果或降低接触求解可靠性来换取表面速度。明显影响画面可读性、等待体验或需要新增生产依赖的取舍须单独说明并确认。

不做：多机器人、多任务编辑器、VLA/VLM、训练数据集、真机连接、实时遥操作、高频推流、多相机录像、云端部署和多人权限。普通镜头适配/旋转缩放属于可读性改进，不扩展为场景编辑器。

普通代码与测试如何组织由执行者负责；新增/升级生产依赖、外部发布、替换操作系统、删除已有运行或降低上述交付目标需要另行确认。本批未执行这些操作；只获取已授权固定模型资产并修改本地代码/文档。
