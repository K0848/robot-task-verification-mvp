## 当前可视化运行方式

1. `npm run build --prefix web/robot_renderer`。
2. `python -m streamlit run app.py`，进入“V2 物理仿真”，启动 baseline 或 offset-grasp。
3. worker 完成后出现回放。按播放/暂停、拖动回放时间、选事件跳转；回放区内切换 Three.js / SVG 会暂停但保持时刻。侧栏渲染选项只服务 V1。
4. 查看下方分层报告、展开原始产物，或下载报告。图中蓝色为工具、橙色为物体、绿色为目标示意；不是仿真机械臂几何重建。

python scripts/verify_v2_browser.py --url http://127.0.0.1:8516 --evidence .tmp-tests/browser-check

## 工程边界

- worker 在独立 Python 进程执行；Streamlit/CLI 只负责启动、轮询和读取。
- V2 renderer payload 标记为 `coordinate_system=mujoco-world`；工具、物体和目标均从轨迹坐标转换，不使用 V1 的 snap/弧线补动画。
- 当前运行时为原生 MuJoCo 3.x，未依赖 robosuite，也未使用 NVIDIA CUDA。
- 当前模型是作品集用轻量平面任务，成功结果只支持声明的仿真条件，不支持真实机械臂或 sim-to-real 结论。
- V1 的 `data/store.json` 和 V2 的 artifact 目录隔离；V2 物理仿真页面消费 V2 artifact，V1 历史页面不混入 V2 运行。
- 父进程超时会终止 worker；Windows 下 status 文件存在短暂读写竞争，代码已做重试，但仍按单用户单任务使用。

## V2 可视化规划

### 目标

可视化的职责是让验证人员在同一时间上下文中看懂“工具做了什么、物体发生了什么、任务为什么成功或失败”。它不是第二个仿真器，也不能重新计算业务结论。

### 数据责任

```text
MuJoCo worker
  → trajectory.jsonl / events.jsonl / summary.json
  → v2_adapter
  → coordinate_system=mujoco-world
  → Three.js 或 SVG
```

后端拥有运行事实、成功判定和失败分类；前端只做坐标比例/轴向转换、时间采样、播放控制、相机和状态展示。V2 不允许使用 V1 的 snap、抬升弧线或失败抖动替代物理轨迹。

### 页面结构（当前切片）

| 区域 | 展示内容 | 数据来源 |
|---|---|---|
| 主视图 | 工具、物体、目标、阶段和轨迹 | `trajectory.jsonl` |
| 运行状态 | run ID、策略、running/成功/失败、轨迹帧数 | `status.json`、`meta.json` |
| 结果报告 | 成功条件、失败观察、分类、可能原因、证据范围 | `summary.json` |
| 播放控制 | 播放、暂停、静态回放、倍速和时间位置 | trajectory offset + renderer |
| 结构化详情 | 当前帧的工具/物体/目标 x/y/z、抓取约束、释放状态 | 当前 trajectory frame |

当前先保持单主视图 + 结构化报告，不加入多机器人、多视角、点云、摄像头和复杂 3D 场景编辑。

### 参考调研与适配

- Foxglove 将 3D、Plot、State Transitions、Raw Messages 和 Log 作为可组合面板，并通过时间戳和坐标变换保证空间数据与回放时间一致；本项目只借鉴“空间视图 + 时间上下文 + 原始数据可查”的关系，不复制其完整平台。
- Rerun 将 viewport、selection、timeline 和 state timeline 组合在一个 viewer 中；本项目借鉴“时间轴定位阶段/事件”的方式，暂不引入 Rerun 依赖。

参考：

- https://docs.foxglove.dev/docs/visualization/panels/3d
- https://docs.foxglove.dev/docs/visualization/panels/plot
- https://docs.foxglove.dev/docs/visualization/panels/raw-messages
- https://rerun.io/docs/reference/viewer/overview
- https://rerun.io/docs/reference/viewer/timeline

### 视觉验收规则

1. baseline：工具和物体按照轨迹移动，释放后物体位于目标区域。
2. offset-grasp：物体未建立抓取约束，不能被 renderer 强行吸附到工具。
3. 页面显示的成功/失败必须与 `summary.json` 一致。
4. SVG 回退只改变展示方式，不改变运行结论。
5. 原生浏览器中需要补做一次视觉确认；AppTest 已验证 baseline/offset-grasp 页面路径无异常。

## 当前未验证

- 真机几何、姿态/关节精确重建不在该轨迹示意视图范围；本轮已经核验 Chromium 的 3D/SVG 回放。
- robosuite/WSL2 fallback；
- 多 episode、多任务、多机器人、VLA/VLM 推理和真实机器人部署。
